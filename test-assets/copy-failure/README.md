# 복사 실패 시험 환경

이 폴더는 ACL이나 파일 소유권을 변경하지 않고 다른 프로세스의 독점 잠금 때문에 발생하는 Robocopy 복사 실패를 재현한다. 현재 `/Z /COPY:DAT` 조합에서는 Robocopy가 잠긴 파일의 특성을 처리하다 `오류 2`를 보고할 수 있으며, Windows 버전과 작업 단계에 따라 다른 오류 코드가 보고될 수도 있다.

이 환경은 `잠금 프로세스 확인`과 우클릭 `정상 종료 요청` 검증에 사용한다. 오류 코드 5와 `관리자 권한으로 다시 시도`를 검증하려면 `test-assets\elevated-retry` 환경을 사용한다.

## 시험 순서

1. PowerShell에서 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-Failure-Test.ps1`을 실행한다.
2. 프로그램 원본 폴더로 이 폴더의 `source`를 선택한다.
3. 대상 폴더로 이 폴더의 `destination`을 선택한다.
4. 빠른 확인을 위해 재시도 횟수와 재시도 간격을 각각 `0`으로 설정한다.
5. 복사를 시작한다.
6. 정상 파일은 복사되고 `잠긴 파일.txt`는 실패하는지 확인한다.
7. 메인 화면의 `오류 파일 (1)`을 열어 Robocopy가 실제로 반환한 오류 유형·코드와 원본·복사 후 경로를 확인한다. 현재 시험 구성에서는 `경로 오류 / 코드 2`가 나타날 수 있다.
8. `잠금 프로세스 확인`에서 PowerShell 프로세스와 PID가 표시되는지 확인한다.
9. 시험이 끝나면 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-Failure-Test.ps1`을 실행한다. 이 스크립트는 강제 종료하지 않고 정상 해제 신호를 보낸다.
10. 오류 창에서 `선택 항목 다시 시도`를 실행해 잠금 해제된 파일만 복사되는지 확인한다.

대상 폴더의 기존 결과는 스크립트가 자동 삭제하지 않는다. 반복 시험 전에는 필요한 경우 사용자가 대상 폴더의 복사 결과만 직접 정리한다.
