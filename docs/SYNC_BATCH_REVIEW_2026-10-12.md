# 대상 전용 항목의 삭제·유지 확인 통합

## 원인

`OneWaySyncPlanner`는 이미 하위 폴더를 재귀 검사하고, 확인 창의 폴더 선택도 하위 항목에 적용한다. 하지만 탐색기 다중 선택은 `ShellCopyRequestFactory`에서 선택한 폴더별 Robocopy 작업으로 나뉜다. `ExecuteJobAsync`가 작업마다 새 확인 창을 열어, 같은 최상위 대상 폴더의 하위 작업에서도 반복 확인이 발생했다. 모두 유지한 빈 선택도 다음 작업에 전달되지 않았다.

파일만 선택한 비재귀 작업에서도 기존 검사기가 하위 폴더를 재귀 검사하는 별도 범위 문제를 확인했다.

## 수정

- 실행 중인 동기화 작업과 대기 중인 동기화 작업의 검사 결과를 한 계획으로 모은다. 공통 최상위 대상 경로 기준으로 하위 항목을 표시하고, 중복 대상은 한 번만 표시한다.
- 대상 루트 전체의 무관한 파일을 삭제 후보로 삼지 않는다. 탐색기에서 선택한 작업 범위만 통합한다.
- 한 번의 확인 결과를 각 작업 ID에 연결한다. 삭제 선택뿐 아니라 모두 유지한 빈 선택도 기록한다. 이후 하위 작업과 일시정지 후 재개는 동일한 결정을 사용한다.
- 새 작업 추가 또는 작업 경로·옵션 수정은 새로운 확인 범위로 처리한다. 이전 경로의 삭제 승인으로 수정된 작업을 삭제하지 않는다.
- 다른 작업의 원본에 존재하는 대상 파일은 대상 전용 항목에서 제외한다. 삭제는 각 작업의 복사가 성공한 뒤 기존 삭제 서비스에서 원본 부재와 대상 루트 범위를 다시 확인한다.
- 비재귀 작업은 대상의 하위 폴더를 검사하지 않는다. 기존 폴더 선택의 하위 항목 전파와 선택하지 않은 파일 유지 동작은 유지한다.

## 검증 및 배포

- 전체 솔루션 Release 빌드: 경고 0, 오류 0.
- 관련 Core 테스트 42개 통과: 형제 작업·중첩 폴더의 통합 목록, 한글·공백·특수문자 경로, 모두 유지 결정 저장, 선택 삭제의 작업별 분배, 다른 작업 원본 보호, 중복 제거, 비재귀 검사 범위, 기존 삭제·동기화·인자·종료 코드 회귀.
- Windows 테스트 2개 통과. 실제 WPF 확인 창을 열어 두 하위 작업에서 모두 유지와 모두 삭제의 확인이 각각 한 번만 표시되는지 검사했다. 이전 미니 UI 오류 복귀도 같은 STA 테스트에서 확인한다.
- 결과 파일: `tests/RoboCopy_GUI_Kr.Core.Tests/TestResults/sync-batch-review.trx`, `tests/RoboCopy_GUI_Kr.Windows.Tests/TestResults/sync-batch-review-ui.trx`.
- 기존 `artifacts/development/RoboCopy_GUI_Kr_Development/app`에 GUI, Worker, Agent를 반영했다. 기존 source와 tests도 갱신했다. 별도 배포 폴더는 만들지 않았으며 설치기 EXE는 재생성하지 않았다.
