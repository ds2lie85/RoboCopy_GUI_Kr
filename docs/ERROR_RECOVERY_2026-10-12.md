# 미니 UI 오류 복구 및 실행 파일 잠금 진단

## 확인한 문제

- 미니창은 성공 완료일 때만 종료하고, 실패 완료일 때 메인창으로 복귀하지 않았다. 실패 시 진행률이 100% 미만으로 남아 멈춘 작업처럼 보일 수 있었다.
- 잠금 조회는 원본 파일이 존재하면 원본만 조회했다. 대상 파일이 실행 중인 경우 대상의 잠금을 놓칠 수 있었다.
- 이미지의 오류 코드 32는 공유 위반이다. 관리자 권한 재시도는 파일 사용 중 상태를 해제하지 않는다. 이미지의 EXE/DLL 이름은 현재 앱의 실행 파일과 일치하지만, 이미지의 전체 경로와 당시 PID가 없어 자기 덮어쓰기 여부를 단정할 수는 없다.

## 변경한 복구 흐름

1. 작업을 시작한 뒤 대기열 실행이 끝났고 일시정지 상태가 아니며 대기 작업이 없으면 실패 작업 또는 미해결 오류 파일을 확인한다.
2. 오류가 남으면 메인창을 표시하고 활성화한다. 기존 오류 관리 창은 소유자를 메인창으로 바꾸고, 없으면 새로 연다.
3. 미니창을 닫되 앱 전체를 종료하지 않는다. 정상 완료 자동 종료는 유지한다.
4. 잠금 조회는 존재하는 원본과 대상을 모두 조회한다. 현재 프로세스의 EXE, 네이티브 모듈, 관리 어셈블리는 직접 확인하여 Restart Manager가 호출자를 누락하거나 자기 파일의 OS 조회가 실패해도 현재 사용 사실을 식별한다. 다른 경로의 조회 오류는 숨기지 않는다.
5. 현재 앱이 대상 파일을 사용 중이면 오류 관리 창에서 원인과 조치 방법을 표시한다. 해당 파일은 반복 재시도에서 제외한다. 현재 앱에 대한 정상 종료 요청도 막는다. 다른 프로세스의 종료 승인 절차는 유지한다.
6. 조회 결과가 없다는 메시지는 잠금 부재를 보증하지 않음을 설명한다. 다른 세션, 보안 프로그램, 원격 서버의 잠금은 별도 확인이 필요할 수 있다.

## 현재 앱의 대상 파일 잠금 조치

프로그램 **전체 폴더**를 복사 원본·대상 밖의 별도 위치에 준비하여 실행한다. 기존 대상 위치에서 실행한 프로그램은 사용자가 정상 종료하고 새 위치의 프로그램에서 실패 파일을 다시 복사한다. EXE만 옮기면 의존 DLL이나 Worker가 빠질 수 있다. 자동 강제 종료, ACL 변경, 파일 삭제나 지연 덮어쓰기는 추가하지 않았다.

## 검증

- 별도 중간 출력 경로 `artifacts/validation/error-recovery`에서 전체 솔루션 Release 빌드: 경고 0, 오류 0.
- 관련 테스트: Core 46개, Windows 2개, 총 48개 통과. 오류 전환 정책, 원본/대상 중복 제거, 한글·공백·특수문자 경로, Robocopy 인자와 종료 코드, 현재 관리 DLL 감지를 포함한다.
- WPF 회귀 검증은 65%에서 미해결 오류가 남은 상황과 기존 오류 창이 미니창 소유인 상황을 모두 검사한다. 앱을 유지하면서 메인창/오류 창 표시와 소유자 변경, 오류 목록 보존, 자기 파일 안내 표시를 확인했다.
- 전체 테스트도 실행했다. 마지막 전체 실행은 Core 281/285, Windows 14/15 통과. 실패는 파일 정리 잠금(DestinationFileProgressMonitor, ShellCopyRequestFactory, MtBenchmark 2개) 및 ExplorerPackageRegistration의 생성 Manifest 누락이다. 변경한 복구 기능의 관련 테스트는 별도 실행에서 모두 통과했다.
- 테스트 결과: `tests/RoboCopy_GUI_Kr.Core.Tests/TestResults/error-recovery-focused.trx`, `tests/RoboCopy_GUI_Kr.Windows.Tests/TestResults/error-recovery-focused.trx`, 전체 실행 `error-recovery-isolated.trx`.

기존 빌드 출력의 Agent 중간 DLL은 매핑된 상태로 쓰기 실패하여 별도 출력 경로로 빌드했다. 실행 중인 프로세스를 종료하지 않았다.

## 기존 배포 경로 반영

`Run-Development.ps1`이 사용하는 기존 `artifacts/development/RoboCopy_GUI_Kr_Development/app`에 수정된 자체 포함 GUI, Elevated Worker, Agent를 반영했다. 변경 소스와 테스트도 같은 패키지의 기존 `source`, `tests` 경로에 반영했다. 주요 실행 파일과 DLL의 SHA-256으로 복사 일치를 확인했다. 별도 수정본 배포 폴더는 제거했으며, `artifacts/validation/error-recovery`는 중간 빌드·테스트 출력이다. 기존 설치기 EXE와 과거 릴리스 압축본은 재생성하지 않았다.
