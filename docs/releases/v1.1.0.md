# RoboCopy_GUI_Kr 1.1

This is the first public 1.1 release after version 1.0. It combines all previously unpublished 1.1 improvements and the fixes completed on October 12, 2026. The application version is **1.1**, the package version is **1.1.0**, and the file/assembly version is **1.1.0.0**.

1.0 이후 처음 공개하는 1.1 릴리스입니다. 이전에 공개하지 않았던 1.1 개선 사항과 2026년 10월 12일까지 완료한 수정 사항을 모두 포함합니다. 앱 표시 버전은 **1.1**, 패키지 버전은 **1.1.0**, 파일·어셈블리 버전은 **1.1.0.0**입니다.

The application continues to provide a Korean Windows interface for Robocopy, including copying, verified moves, one-way backup, continuous synchronization through a tray agent, profiles, job queues, preview, and automatic thread recommendations. The changes below describe what has improved since 1.0.

Robocopy용 한국어 Windows UI의 복사, 검증 후 이동, 단방향 백업, 트레이 에이전트 기반 지속 동기화, 프로필, 작업 큐, 미리보기 및 자동 스레드 추천 기능을 유지합니다. 아래는 1.0 이후 개선된 내용입니다.

## Windows 11 Explorer integration / Windows 11 탐색기 연동

Selected files and folders can use **Robocopy로 복사** directly from the Windows 11 primary context menu, without opening a submenu first. The destination folder background provides paste, move, one-way backup, and continuous synchronization commands. Existing classic context-menu integration remains available.

선택한 파일·폴더의 Windows 11 기본 우클릭 메뉴에서 **Robocopy로 복사**를 하위 메뉴 없이 직접 클릭할 수 있습니다. 대상 폴더의 빈 공간에서는 붙여넣기, 이동, 단방향 백업 및 지속 동기화 명령을 제공합니다. 기존 방식의 탐색기 우클릭 메뉴도 유지합니다.

The Explorer extension uses an external COM server and package identity. Development and installed packages use separate identities so their registrations do not replace one another. Selection handling covers Korean text, spaces, and special characters; paste commands are limited to suitable folder contexts. Windows controls the placement and order of menu entries.

탐색기 확장은 외부 COM 서버와 패키지 식별 정보를 사용합니다. 개발본과 설치본의 식별자를 분리하여 서로의 등록을 교체하지 않도록 했습니다. 한글·공백·특수문자가 포함된 선택 경로를 처리하며, 붙여넣기 명령은 적절한 폴더 위치에서 제공됩니다. 메뉴 항목의 위치와 순서는 Windows가 결정합니다.

## Optional installer setting / 선택형 설치 옵션

The Windows 11 installer offers **Enable Developer Mode for primary context-menu registration**, unchecked by default. The option explains its purpose, that the setting applies to the whole PC, the relaxation of app-installation restrictions, and possible unexpected risks. Enabling it requires an additional confirmation and administrator approval for the setting-change helper only. Paid signing certificates or signing services are not used in this release.

Windows 11 설치기에 **기본 우클릭 메뉴 등록용 개발자 모드 활성화** 옵션을 추가했으며 기본값은 미체크입니다. 사용 목적, PC 전체에 적용되는 설정, 앱 설치 제한 완화 및 예기치 못한 위험을 안내합니다. 활성화에는 추가 확인과 설정 변경 도우미에 한정된 관리자 승인이 필요합니다. 이번 버전은 유료 서명 인증서나 서명 서비스를 사용하지 않습니다.

If Developer Mode is already enabled, primary-menu registration can proceed according to the Explorer integration selection. Leaving the option unchecked, declining administrator approval, or failing registration preserves the installed application and classic menus. Uninstall removes the package associated with the installation path and leaves the PC's Developer Mode setting unchanged.

개발자 모드가 이미 켜져 있으면 탐색기 연동 선택에 따라 기본 메뉴를 등록할 수 있습니다. 옵션을 선택하지 않거나 관리자 승인을 취소하거나 등록에 실패해도 설치된 앱과 기존 메뉴를 유지합니다. 제거 시 해당 설치 경로에 연결된 패키지를 정리하며 PC의 개발자 모드 설정은 그대로 둡니다.

## Overwrite selection and copy reliability / 덮어쓰기 선택 및 복사 안정성

Large overwrite-selection lists are virtualized to reduce UI stalls and memory growth. Approved overwrites from a single source proceed directly. A final-file selection is required only when multiple selected sources, such as search results, map to the same destination path.

대량 덮어쓰기 선택 목록을 가상화하여 UI 멈춤과 메모리 급증을 개선했습니다. 단일 원본의 승인된 덮어쓰기는 바로 처리하며, 검색 결과 등 여러 원본이 동일한 대상 경로로 모이는 경우에만 최종 파일을 선택합니다.

Read-only replacement and temporary-file cleanup have been corrected. Temporary files are kept writable until replacement completes; approved replacement clears only the destination's read-only attribute when needed and restores it if replacement fails. Source attributes and ACLs are not changed. Cleanup failures retain the original copy error instead of hiding it.

읽기 전용 파일 교체와 임시 파일 정리 문제를 수정했습니다. 교체가 끝날 때까지 임시 파일을 쓰기 가능한 상태로 유지하고, 승인된 교체에 필요한 경우 대상의 읽기 전용 속성만 해제하며 실패 시 복원합니다. 원본 속성과 ACL은 변경하지 않습니다. 정리 실패가 최초 복사 오류를 가리지 않도록 했습니다.

Direct-file copy failures now contribute to failed-file and failed-byte summaries. Later successful jobs do not erase an earlier failure state. A completion display or a zero-failure summary alone does not constitute byte-by-byte verification of all copied contents; verified move mode continues to use its separate content-verification step.

직접 파일 복사 실패를 실패 파일·바이트 요약에 포함합니다. 뒤의 작업이 성공해도 앞선 실패 상태가 사라지지 않도록 했습니다. 완료 화면이나 실패 0 요약만으로 전체 복사 내용의 바이트 검증이 완료되었다는 의미는 아닙니다. 검증 후 이동은 기존의 별도 내용 검증 단계를 유지합니다.

## Mini-window recovery and lock diagnosis / 미니창 오류 복구 및 잠금 진단

Backup and conflict dialogs now select a visible window owner, correcting errors caused by a hidden main window while the mini UI is active. When queued work finishes with failed jobs or unresolved error files, the application returns to the main window and opens or reuses the error-file manager. The mini window closes while the application remains available for recovery; normal successful-completion behavior is retained.

미니 UI 사용 중 숨겨진 메인창을 소유자로 지정하여 발생하던 백업·충돌 확인 창 오류를 수정했습니다. 대기열 실행이 끝났을 때 실패 작업이나 미해결 오류 파일이 남으면 메인창으로 복귀하고 오류 파일 관리 창을 열거나 재사용합니다. 앱은 오류 복구를 위해 유지한 채 미니창을 닫으며, 정상 완료 동작은 유지합니다.

Lock diagnosis checks both existing source and destination paths instead of checking only the source. It also identifies executable files and loaded DLLs used by the running application. Files locked by the application itself are excluded from repeated retries, and the error manager explains how to close that instance normally and run the complete application folder from a separate location before retrying. Other processes still require the existing explicit shutdown approvals.

잠금 진단이 원본만 검사하던 문제를 수정하여 존재하는 원본·대상 경로를 모두 검사합니다. 현재 앱이 사용하는 실행 파일과 로드된 DLL도 식별합니다. 앱 자체가 잠근 파일은 반복 재시도에서 제외하고, 기존 실행본을 정상 종료한 뒤 전체 앱 폴더를 별도 위치에서 실행하여 재시도하는 방법을 안내합니다. 다른 프로세스의 종료에는 기존의 명시적 승인 절차를 유지합니다.

## Combined synchronization review / 동기화 확인 통합

Queued one-way backup jobs share one review of destination-only items within the selected job scopes. Entries are shown relative to the common top-level destination and duplicates are removed. Both deletion choices and a keep-all decision are remembered for subsequent sub-jobs and paused/resumed work, avoiding repeated confirmation for each child folder.

대기열의 단방향 백업 작업은 선택한 작업 범위의 대상 전용 항목을 한 번에 확인합니다. 공통 최상위 대상 경로를 기준으로 표시하고 중복 항목은 제거합니다. 삭제 선택뿐 아니라 모두 유지한 결정도 후속 하위 작업과 일시정지 후 재개에 적용하여 하위 폴더마다 반복 확인하던 문제를 개선했습니다.

Unselected folders and files are protected. Files present in another queued job's source are excluded from destination-only deletion candidates, and non-recursive jobs no longer scan destination subfolders. Each job deletes only its approved items after its own copy succeeds, with the existing source-absence and destination-boundary checks. Added jobs or changed paths/options require a new review scope.

선택하지 않은 폴더·파일을 보호합니다. 다른 대기 작업의 원본에 존재하는 파일은 대상 전용 삭제 후보에서 제외하고, 비재귀 작업이 대상 하위 폴더까지 검사하던 문제를 수정했습니다. 각 작업은 자체 복사가 성공한 뒤 승인된 항목만 삭제하며 원본 부재 및 대상 경계 검사를 유지합니다. 작업 추가나 경로·옵션 변경은 새 확인 범위로 처리합니다.

## Benchmark cleanup and distribution / 성능 측정 정리 및 배포

Cleanup of temporary benchmark output retries transient sharing locks a limited number of times. Cleanup remains restricted to the benchmark's temporary directory and preserves source data and neighboring directories.

성능 측정용 임시 출력 정리는 순간적인 공유 잠금을 제한된 횟수만큼 재시도합니다. 정리 범위는 측정용 임시 폴더로 제한하고 원본 데이터와 주변 폴더는 보존합니다.

Installer naming and checksums follow the central version definition. Release preparation collects source, tests, scripts, documentation, the installer, and SHA-256 checksums while excluding SDKs, caches, build outputs, generated test state, and credentials. Both installer payloads retain the project license and the bundled runtime packages' original notices.

설치기 이름과 체크섬은 공통 버전 정의를 따릅니다. 배포 준비 과정에서 소스, 테스트, 스크립트, 문서, 설치기 및 SHA-256 체크섬을 모으고 SDK, 캐시, 빌드 산출물, 생성된 시험 상태 및 인증 정보는 제외합니다. 설치기의 두 페이로드 모두 프로젝트 라이선스와 동봉한 런타임 패키지의 원본 고지를 유지합니다.

## Download and requirements / 다운로드 및 실행 조건

Download **RoboCopy_GUI_Kr_Setup_v1.1_x64.exe** and **SHA256SUMS.txt**. **RoboCopy_GUI_Kr_Source_v1.1.0.zip** is also provided for source distribution. Compare downloaded files with the matching checksum entries. The installer includes an offline self-contained application, so a separately installed .NET SDK is not required.

**RoboCopy_GUI_Kr_Setup_v1.1_x64.exe**와 **SHA256SUMS.txt**를 내려받으세요. 소스 배포용 **RoboCopy_GUI_Kr_Source_v1.1.0.zip**도 제공합니다. 다운로드한 파일의 해시를 해당 체크섬 항목과 비교하세요. 설치기는 오프라인 자체 포함 앱을 제공하므로 별도 .NET SDK 설치는 필요하지 않습니다.

The declared minimum is Windows 10 version 1607 x64 (build 14393). Primary context-menu integration is a Windows 11 feature; classic menus remain available. This installer is unsigned, so Windows may display download or execution warnings. Windows 7/8.1 and native ARM64 builds are not provided.

최소 환경 기준은 Windows 10 버전 1607 x64(빌드 14393)입니다. 기본 우클릭 메뉴 연동은 Windows 11 기능이며 기존 메뉴도 제공합니다. 서명되지 않은 설치기이므로 Windows의 다운로드·실행 경고가 표시될 수 있습니다. Windows 7/8.1 및 ARM64 네이티브 빌드는 제공하지 않습니다.

## Validation / 검증

The integrated source was built and tested on Windows 10 x64 build 19045 with .NET SDK 8.0.425. The Release solution build completed without errors, and **303 tests passed** (289 Core and 14 Windows); **one Windows 11 package-registration test was skipped**. The installer was built and its embedded payloads inspected. Actual installation/removal, operation on another computer, and the final Windows 11 menu behavior of this installer require separate manual checks; earlier internal-build results do not establish those checks for this installer.

통합 소스는 Windows 10 x64 빌드 19045, .NET SDK 8.0.425 환경에서 빌드·시험했습니다. Release 솔루션 빌드는 오류 없이 완료했고 **303개 테스트가 통과**했습니다(Core 289개, Windows 14개). **Windows 11 패키지 등록 테스트 1개는 건너뛰었습니다.** 설치기를 생성하고 내장 페이로드를 검사했습니다. 이 설치기의 실제 설치·제거, 다른 컴퓨터 실행 및 최종 Windows 11 메뉴 동작은 별도 수동 확인이 필요하며 이전 내부 빌드의 확인 결과로 대신하지 않습니다.
